# Recap

Decided on 2026-10-15 (popups in the session that shipped Deep search). Three tickets: 1 first, then 2 and 3 in parallel.

## Goal

The picker's preview shows the last few messages, which is the tail of a Session, not what it is about. A **Recap** is three short lines a small model writes about a Session, shown in a box above those messages:

```
goal  cheapest padel for 4 in Oslo, 21:00-24:00
done  top 3 found; showers confirmed at Bærum and Just Padel
next  decide between a membership and paying per game
```

Called Recap, not summary: CONTEXT.md already uses "summary" for Claude Code's auto-generated title and for the resume-from-a-summary offer.

## Rules

- **Opt-in.** `[recap] enabled = true` in `~/.config/unpause/config.toml`. Off by default because it sends Session text to Haiku. When off, nothing is generated and the picker shows no box.
- **Model call** exactly like autoname (ADR 0008): `claude -p --model haiku` under the Session's own Account, no session persistence, hooks disabled, no tools, no MCP, from the temp dir, with the `UNPAUSE_AUTONAME` guard (or a sibling guard) so the hook can't recurse.
- **Input** (bounded, about 8,000 characters): repo, branch, Title, then the Session's talk in file order using Deep search's rules (prompts and replies only, no tool output, no injected text), keeping the first prompt and as much of the end as fits.
- **Output**: three lines labelled `goal`, `done`, `next`, each at most about 100 characters. A reply that doesn't parse into those three lines is rejected, not stored.
- **Storage**: a cache file next to the index (`~/.cache/unpause/recaps.json`), keyed by Session id, holding the three lines, the transcript size it was made from, and when. Never written into the Transcript (ADR 0012). Deleting the file loses nothing but Recaps.
- **Outdated**: a Recap whose transcript has grown since it was made is shown dim with `· earlier` after the label, and is regenerated by backfill or the next hook run.
- **Never** for Live Sessions (unfinished), Cowork Sessions (read-only Account), empty Sessions or sidechains.

## Ticket 1: Recap one Session, end to end

- `unpause recap --session <id>`: builds the input, calls Haiku, parses, stores. Prints the Recap. Errors are reported, nothing is stored.
- Config `[recap] enabled`; with it off, `unpause recap` says how to turn it on and exits non-zero.
- The picker preview shows a bordered box with the three lines between the metadata block and the messages, when Recaps are enabled and the Session has one. No box otherwise.
- Tests: input building (talk only, bounded, first prompt kept), reply parsing (good, extra chatter, missing line, too long), store round trip, picker renders the box from a fake store, disabled config.

## Ticket 2: Backfill (blocked by 1)

- `unpause recap` with no `--session`: Recaps Sessions that have none or an outdated one, newest first, skipping Live, Cowork, empty and sidechain Sessions. `--limit N` (default 20, 0 = all). `--dry-run` lists which Sessions would be done and stops. Progress one line per Session; one Account's failed login skips its remaining Sessions, like autoname.
- `unpause doctor` shows whether Recaps are on and how many Sessions have one.
- Tests: selection (missing, outdated, skipped kinds, order, limit), dry run makes no calls.

## Ticket 3: Hook, outdated marker, toggle (blocked by 1)

- `unpause hook session-end` also starts a detached `unpause recap --session <id>` when Recaps are enabled (alongside autoname, same log file).
- Outdated Recaps render dim with `· earlier`.
- `^t` in the picker hides or shows the Recap box for this run; footer shows `^t recap` only when Recaps are enabled.
- Tests: hook starts the recap child only when enabled, outdated detection, `^t` toggles the box.

## Amendments after the real-data check (v0.8.1)

- The talk goes inside `<transcript>` tags with the task repeated after it, and the system prompt says the transcript is material to recap, not a conversation to join. Without this, Haiku answered the session's last question instead of recapping it.
- A line longer than 120 characters is clipped with `…` instead of rejecting the reply; Haiku often runs long on `done`.
